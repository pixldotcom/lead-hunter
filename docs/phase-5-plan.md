# Phase 5 implementation plan and risks

1. Preserve the uncommitted local baseline, lead v1 schema and durable drafts. Reuse the existing analyzer/API, score primitives, CSV parser and validated lead promotion. No new packages or search API.
2. Add an independent validated discovery v1 store: preferences, domain-deduplicated candidates, evidence, decisions, batches, review timestamps and optional proposal concept metadata. Preserve corrupt originals and reject conflicting or failed writes without touching leads.
3. Deliver paste/domain/CSV input plus explicit browser-assisted search links; sequential bounded quick scans with abort, saved progress, cached results and selective refresh. No SERP scraping, crawl, provider credentials or claims that opening a search discovered candidates.
4. Rank candidates using mapped verified findings, user-confirmed service fit/commercial relevance, explicit contact evidence and freshness. Require a human review with concrete evidence before qualification/promotion. Keep existing lead scoring/backup semantics intact.
5. Add a compact queue with decisions, inline evidence review, deep-review checklist, promotion into existing leads, qualified-only proposal templates, safe HTML concept preview/export and existing outreach/draft handoff. Record review/contact outcomes independently and summarize actual lead outcomes for batch-linked domains.
6. Verify external resource links from official documentation; use manual Chrome screenshot/Lighthouse steps instead of adding remote screenshot infrastructure that would risk SSRF or execute arbitrary websites in the analyzer.
7. Add domain, persistence, cancellation/cache, qualification, promotion, concept-security and browser workflow coverage. Run all requested checks and document automation/manual boundaries.

Risks and mitigations: static HTML cannot verify real journeys, CWV or demand; show limitations and require human confirmation. Agency existence earns no commercial-fit points; agency qualification requires a sourced development-support reason. Metadata issues alone do not establish a high-value project; explicit service relevance and rationale are required and budget stays unknown. Persist batch progress before/after each scan; interrupted work resumes, rejected domains stay remembered. Cross-domain redirects require explicit reviewed evidence association rather than silently merging businesses. React text rendering and escaped standalone HTML only; no external HTML execution/assets. No screenshot endpoint or relaxation of analyzer destination protections. Independent stores cannot be transactional with leads: promote leads first and retry/reconcile association by normalized domain. Existing v1 backups exclude discovery and draft data; provide a separate discovery export/recovery download.
